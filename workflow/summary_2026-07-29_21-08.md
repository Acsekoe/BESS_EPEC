## Price-only epsilon formulation

The direct `--strategic-epsilon-penalty` is now

`epsilon * sum(p_bid_charge**2 + p_offer_discharge**2)`.

It has no direct MW, MWh, quantity-offer, or withheld-quantity term. A model
construction check found exactly 432 price variables and no capacity, energy,
or quantity variables in the epsilon expression. The separate proximal
continuation remains unchanged and still penalizes movements in MW/MWh,
withheld quantities, and normalized prices relative to the previous strategy.

## Remaining convergence caveat

At iteration 20 all solves were optimal, there were no projection events, and
simultaneous charging/discharging was negligible. Capacity and quantity
strategies were essentially stationary:

- maximum capacity step: about 0.000074 MW-equivalent;
- maximum withheld-offer step: about 0.000066 MW;
- I3 price step: about 0.053 EUR/MWh;
- I4 price step: about 0.716 EUR/MWh versus the 0.5 tolerance.

The run passed all tests at iterations 17 and 19 for one sweep each, but never
for the required three consecutive sweeps. It is therefore a regularized,
economically stable candidate rather than a formally converged equilibrium.
Most final price coordinates are not accepted, so the remaining price movement
may be economically inactive; this has not yet been decomposed coordinate by
coordinate.

## Solve-order sensitivity implementation

Both diagonalization CLIs now accept, for example,

`--investor-order I3 I1 I4 I2`.

The option validates that every configured investor appears exactly once. The
selected order is written as `investor_solve_order` in checkpoint, run-config,
and summary JSON files. This permits an auditable 24-permutation Gauss-Seidel
sensitivity without changing investor identities, WACC, or generation shares.

The intended overnight experiment runs every permutation sequentially for:

1. the maintained capacity-only EPEC; and
2. the two-sided price/quantity strategic-operation EPEC with price-only
   epsilon `1e-6`, damping 0.7, 20 iterations, and the proximal staircase of
   1 EUR/MW^2/day every five iterations.

All runs use the same 100 MW nodal limit and scarcity-95 generator calibration.
Results belong under the separate root
`model/output/order_sensitivity_2026-07-29/`, with one directory per model and
solve order plus a root `run_status.csv` and per-run `console.log`.

function Get-InvestorOrders {
    param(
        [string[]]$Remaining,
        [string[]]$Prefix = @()
    )

    if ($Remaining.Count -eq 0) {
        return ,($Prefix -join ",")
    }

    foreach ($item in $Remaining) {
        $next = @($Remaining | Where-Object { $_ -ne $item })
        Get-InvestorOrders -Remaining $next -Prefix ($Prefix + $item)
    }
}
