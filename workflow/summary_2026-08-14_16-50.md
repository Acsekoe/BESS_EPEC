## Current objective and agreed economics

Create investor heterogeneity through a co-optimised nodal access auction:

- investor \(i\) submits requested power \(q^A_{in}\) and a non-negative
  pay-as-bid willingness to pay \(b^A_{in}\) in EUR/MW-day;
- each investor's total request is capped at 200 MW and each nodal request is
  bounded by the 40 MW nodal limit;
- the ISO/LLP awards only connection power \(x^A_{in}\), jointly with the
  24-hour generation, storage, SOC, and network clearing;
- the investor independently chooses energy capacity \(X^E_{in}\);
- the active investor obeys the technical upper-level bounds
  \(2x^A_{in}\le X^E_{in}\le8x^A_{in}\);
- the LLP uses `P_charge + P_discharge <= x_awarded` and `SOC <= X_energy`;
- investor profit contains LMP storage settlement, owned-generation rent,
  physical degradation, annualised power and energy capex, and the pay-as-bid
  access payment \(b^A x^A\).

Negative access bids remain excluded. MA57 remains the preferred Ipopt linear
solver.

## Important correction made in this chat

The first implementation incorrectly made the investor choose a duration
\(h_{in}\) and defined energy mechanically as
\(X^E_{in}=h_{in}x^A_{in}\). That auctioned power indirectly determined MWh,
contrary to the intended economics.

It also created cubic relaxed-KKT constraints. For example,

\[
(h_{in}x^A_{in}-SOC_{int})(-\delta_{int})\le\varepsilon
\]

contains \(h\,x^A\,\delta\). Awarded-MW complementarity contained another
cubic family because its reduced cost included \(h\delta\).

The implementation now uses independent upper-level `EnergyCapacity[n]`.
Consequently,

\[
(X^E_{in}-SOC_{int})(-\delta_{int})\le\varepsilon
\]

is quadratic, and awarded-MW stationarity no longer contains an SOC-duration
term. The corrected four-player best-response model has 6,590 variables,
11,708 constraints, 5,153 quadratic constraints, and **zero cubic
constraints**.

During a nonconverged simultaneous Jacobi iterate, the common post-update
award can differ from each investor's counterfactual best-response award.
Independent MWh is therefore not silently rescaled after the common clearing;
temporary 2--8 hour violations in the common iterate are exported and must be
zero before claiming equilibrium. This treatment must be part of the next
mathematical review.

## Initialization and runtime findings

The original command omitted initial access-strategy flags, so it started from
0 MW requests, 0 EUR/MW-day bids, and the minimum energy ratio. The exact
HiGHS initializer was mathematically correct—initial constraint violation was
about `1.9e-12`, KKT products about `1.8e-12`, and the primal-dual gap zero—but
79.6% of the 6,590 variables were zero. All four Ipopt processes exhausted the
300-second CPU limit. Pyomo reported `maxIterations`, although Ipopt's actual
message was `Maximum CPU Time Exceeded`. Failed responses were discarded, so
the printed zero deviations meant “state retained,” not convergence.

An interior start of 5 MW per investor-node, 20 EUR/MW-day, and 3-hour initial
MWh was exact and much more useful. However, using one identical bid at every
node creates ties and does not reflect nodal differences. The next maintained
change must support **different initial access bids by node** (and preferably
small deterministic investor differentiation if needed). The current CLI only
accepts one scalar `--initial-access-bid`, so this is not implemented yet.

Model size alone did not explain runtime. The rejected access formulation was
smaller than strategic price-quantity but contained 234 cubic constraints,
global access-allocation coupling, flat directions at zero request/award, and
bid-order active-set changes at scarce nodes. The corrected model removes the
cubics but remains a nonconvex relaxed MPEC.

heterogeneity, but none of these values should be reported as an equilibrium

## Required next workflow

1. Begin by auditing the corrected mathematics, especially whether the
   technical ratio should reference awarded MW and how rival/common feasibility
   is represented during Jacobi iterations.
2. Implement and document node-specific initial access bids. Do not begin the
   main run from one identical scalar bid at all nine nodes.
3. Start from positive interior requests and independent energy, but run the
   first few sweeps (suggested 3--5) with `--proximal-penalty 0`. This lets the
   game find a meaningful economic region without anchoring bids to arbitrary
   initial values.
4. Once a plausible state exists, resume from its format-v7 checkpoint with
   `--proximal-penalty 0.01 --allow-proximal-penalty-change`. The proximal term
   should then act only as an anti-cycling stabiliser.
5. Retain MA57 and benchmark two versus four parallel workers if memory
   contention remains material. Use a 600-second response limit for the main
   experiment.
6. Before claiming equilibrium, require optimal responses, raw MW/MWh/request/
   bid residuals within tolerance for consecutive sweeps, acceptable relaxed-
   KKT products and primal-dual gaps, and zero common-state 2--8 hour
   violations.
