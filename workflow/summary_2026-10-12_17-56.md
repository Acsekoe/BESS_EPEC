# Session summary: why the MPEC bound stalls (root = planner value; multi-node plateau)

Written 2026-10-12 17:56 (Europe/Vienna). Follows `summary_2026-10-12_16-19.md`.
Base commit `a039a82`. Model code unchanged; two diagnostic scripts added.
Run on a cloud machine without a full Gurobi licence: Python 3.13.16,
Pyomo 6.10.1, HiGHS 1.15.1 (LP-file reader only), Clarabel 0.11.1, SCIP 10.0
(pyscipopt 6.3.0), gurobipy 13.0.3 with the size-limited licence (toy only).

## Findings

### 1. The root relaxation is the social-planner problem

Without complementarity the active investor's own multipliers are free, so
prices no longer respond to its capacity X: the duals keep the no-storage
prices (dual value C(0)) and the primal uses the storage (cost C(X)).
`profit_linear` becomes the storage's system cost saving:

    root relaxation = planner value = C(0) - min_X [C(X) + capex(X)]

| case (I1) | root relaxation | planner value | note |
|---|---|---|---|
| IEEE-9 N3 N6 N8 N9, LP variant | 8269.77 | 8269.77 | exact |
| 5-bus all buses, LP variant | 10621.46 | 10621.46 | exact, same MW/MWh |
| IEEE-9 N9, working case (eps 1e-4) | 7742.81 | 10024.86 | same MWh (547.2); Gurobi root was 7742.93 |
| IEEE-9 N3 N6 N8 N9, working case | 8267.92 | 10549.89 | same split as the planner; Gurobi root about 8267.5 |
| 5-bus all buses, working case | 10738.69 | 13099.94 | same MWh at N2, N3, N5 |

LP variant = eps 0, no curtailment and no dispatch slope (pure LP). With the
quadratic terms the root and planner still choose the same capacity; the values
differ by an almost constant amount (2282 on IEEE-9 for both node sets). Removing
only the curtailment slope brings the difference to 0.2-0.6 EUR, so it comes from
the curtailment cost.

Consequences:
- Every complementarity formulation (SOS1, Big-M, products, strong duality)
  must share this root, which matches the 2026-10-12 comparison.
- Valid multiplier bounds or McCormick envelopes of X * mu should not move it
  either (reasoning, not tested): with mu_active free, the planner point stays
  feasible for any bound at least as large as the no-storage multipliers.
- The root gap is economically meaningful: welfare value of the storage
  minus merchant profit (cannibalization). Only branching or decomposition
  can close it.

### 2. The bound stalls with several candidate nodes, not because of the QP terms

SCIP on the LP variant (`mpec_scip_proxy.py`), I1, rivals zero:

| case | result |
|---|---|
| 5-bus N5 | optimal 6971.84 in 1 s (N5 124.3 / 396.6) |
| 5-bus N2 | optimal 2971.73 in 61 s (N2 28.6 / 57.2) |
| 5-bus N2 N5 | optimal 9369.30 in 47 s (N2 25.4 / 50.7, N5 118.8 / 383.3) |
| 5-bus all buses | 240 s: incumbent 9369.30, bound 9430.66 (0.65 %), root 10621 |
| IEEE-9 N9 | optimal 6744.50 in 37 s (172.7 / 456.6) |
| IEEE-9 N3 N6 N8 N9 | 420 s, 274 239 nodes: incumbent 8082.02, bound 8269.77 = root |

- The IEEE-9 four-node bound stays exactly at the root in the LP variant
  too, as with Gurobi on the working case. So the quadratic terms are not the
  cause.
- Hypothesis (not proven): when candidate nodes sit behind the same congestion,
  the planner value is nearly flat in how capacity is split among them. A
  branch at one node lets the relaxation move capacity to another at almost no
  loss, so the bound plateaus. This fits the earlier N3/N9 twin-node finding.
  Not run before the session ended: the IEEE-9 node pairs (N6 N8, N6 N9, N8 N9).
- The LP-variant 5-bus I1 optimum (N2 25.4 / 50.7, N5 118.8 / 383.3) is close
  to the working-case Gurobi incumbent (N2 22.9 / 74.0, N5 118.8 / 380.9), but
  it uses optimistic eps = 0 prices and no curtailment cost, so it is not a
  result of the working model.

## Verification and limitations

- Both scripts reproduce the numbers above (Clarabel on IEEE-9 N9 and 5-bus
  LP variant; SCIP on 5-bus N5). The Gurobi path of `root_vs_planner.py` was
  only run on the toy (root = planner = 140); IEEE-9/5-bus need the full licence.
- Clarabel at eps 1e-4 differs from Gurobi's root by about 0.1 EUR (prices are
  weakly pinned).
- SCIP is a proxy: node counts and times do not transfer to Gurobi, and SCIP
  is very slow on the quadratic objective (the IEEE-9 N9 root QP alone did not
  converge in 300 s), hence the LP variant.
- The variant definition (eps 0, curtailment slopes removed, dispatch slopes 0)
  is stated here, so the results do not depend only on the script.

## Next steps

1. Cheap check with Gurobi on the working case: 5-bus I1 with `--nodes N2 N5`.
   If it proves optimal quickly, the multi-node plateau is confirmed for the
   real model.
2. Run the IEEE-9 node pairs (Gurobi, or `mpec_scip_proxy.py` with the LP
   variant) to see where the plateau starts.
3. Branch on location first: a binary "site open" per candidate node
   (X_power <= headroom * y) with high `BranchPriority`, optionally at most one
   site per congestion pocket as a stated modelling choice. Each leaf then
   behaves like the single-node cases, which close quickly.
4. Use the planner value as a cheap valid upper bound (one convex QP) and to
   discard node subsets whose planner value is below the incumbent.
5. EPEC: accept documented best-response gaps during iteration; push for
   proofs only at the final candidate.
