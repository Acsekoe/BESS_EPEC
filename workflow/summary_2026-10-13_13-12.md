## 1. Bid selection is now part of the MPEC solve

**Decision:** `solve_mpec` in `model/mpec.py` = first solve + `select_bids`;
`run.py mpec --strategic-bids` uses it, so the exported bids, the reclear and
later rival profiles use the selected bids.

**Rule as implemented (changed from the 11:52 design):**
- Kept: capacity fixed at the optimum, the same MPEC (all KKT conditions and
  SOS1 pairs), objective `min sum (bid + d/2)^2 + (offer - d/2)^2`.
- Changed: instead of the profit floor `profit_linear >= pi* - delta`, the
  investor's own charge/discharge and every nodal price are held within 1e-6
  of the optimum (variable bounds). That holds the profit with linear
  constraints only.
- Why: the quadratic profit floor turned the root into an SOCP. Gurobi hit
  "numerical trouble" and, with no incumbent, was still at the root after
  55 s on I1. With the holds, each selection is proven at the root in 0.02 s.
- Holding values (not fixing them) lets Gurobi settle each SOS1 pair itself;
  no active set is guessed by threshold.

**Toy insight (unit test):** the ISO's SOC value is a free dual, so the rule
spreads a markup over the hours that set it. In the four-hour case the 30 EUR/MWh
markup becomes +15 on the hour-2 offer and -15 on the recharge bid, not +30 on
one bid.

**Verification:** the SOS1 check is now relative:
1e-4 EUR + 1e-8 * (|market cost| + |profit|) (`verification_tolerance_eur`,
about 3e-3 EUR on V6). All four V6 runs pass. Before, I3/I4 failed only the
absolute 1e-4 EUR thresholds (2e-3 and 6e-4 EUR errors).

**Limitations:**
- The bids are unique given the first-stage market outcome. With eps = 0 (toy
  LP) two dispatches are optimal (recharge in hour 1 or 3); the selection follows
  whichever the first solve returns. With eps > 0 the outcome is unique.
- `mpec_relaxed` still exports unselected bids.
- The rule is an assumption about rivals (minimal markups: a held-back battery
  reacts as soon as a price moves). Document it in the thesis.

## 2. Scarce hosting capacity: how investors could bid for it (exploratory)

**Reading of the question:** limited connection MW at a node, shared by all
investors (`sum_i X_power[i, n] <= H_n`). Today this is `node_limit` with
headroom = H - rivals' MW, i.e. first come, first served; in a loop the order
decides who gets it (a generalized Nash game with many equilibria).

**Allocation rules considered:**
- **Pay-as-bid, highest bid wins (user idea):** the best response does not
  exist. The winner wants to bid "the rival's value + epsilon", an open set, so
  an MPEC or a loop cannot attain it. Ties occur only at equal values (rare with
  different WACC and ownership), but the epsilon problem is always there.
  Its limit outcome is the second-price outcome.
- **Uniform-price auction (recommended to test next):** each investor demands
  MW at a capacity price p_n [EUR/MW/day], the ISO clears at sum = H_n, and
  everybody pays p_n.
  - With price-taking demand this is the variational equilibrium of the shared
    constraint (one common multiplier = the capacity price; Harker 1991).
  - No epsilon problem: p_n enters each MPEC as a linear fee, and the outer loop
    adjusts p_n.
  - This needs an equilibrium loop; it was not run.
- **Pro-rata scaling of requests:** rewards over-requesting; not recommended.

**Test 1: standalone demand for N5 MW.** Bid MPEC with a fee p on N5 MW, rivals
at zero, all proven optimal within 9 s. The table gives N5 MW chosen:

| fee [EUR/MW/day] | 0 | 25 | 50 | 100 | 200 | 400 |
|---|---|---|---|---|---|---|
| I1 | 107.4 | 66.8 | 45.0 | 3.4 | 0 | 0 |
| I2 | 61.3 | 20.8 | 0 | 0 | 0 | 0 |
| I3 | 136.4 | 91.3 | 63.6 | 20.8 | 0 | 0 |
| I4 | 146.8 | 146.8 | 146.8 | 146.8 | 146.8 | 0 |

Value of N5 to each investor (profit at p = 0 minus profit without N5):

| | I1 | I2 | I3 | I4 |
|---|---|---|---|---|
| value [EUR/day] | 4 684 | 1 170 | 6 992 | 46 869 (about 319 EUR/MW/day) |

N2 MW does not react to the N5 fee.

**Test 2: profit with N5 MW capped at K** (marginal value per MW between caps):

| cap K [MW] | 25 | 50 | 75 | 100 | 125 | 140 | 150 |
|---|---|---|---|---|---|---|---|
| I1 marginal | 89 | 59 | 30 | 9 | 0.2 | 0 | 0 |
| I4 marginal | 169 | 151 | 577 | 86 | 477 | 363 | 496 |

**Reading:**
- I1, I2 and I3 have concave values and smooth demand, so a uniform price
  clears and there is no tie problem.
- I4's value is not concave, so its demand is all or nothing (147 MW or 0
  around 319 EUR/MW/day).
  - Probably the same portfolio mechanism as I3 at N2 (its charge bid sets the
    PV-pocket price); not checked.
  - If H_N5 < 147 MW, possibly no uniform price clears N5 (non-convex, like
    unit-commitment pricing).
  - Then the ISO needs block bids and an allocation rule (second-price or
    uplift). That is where the tie and epsilon issues of pay-as-bid really bite.
- Caveat: these values have rivals at zero. Batteries in the same pocket lower
  each other's value, so a real auction has interdependent values: the demand
  curves must be recomputed at the rivals' allocation (the loop).

**Next steps:**
1. Decide whether hosting capacity is scarce in the thesis cases: the 1000 MW
   default does not bind on V6, so a binding H_n must be chosen and justified.
2. If yes: add an explicit capacity fee parameter per node to the investor
   problem, then a price-adjustment loop around the bid-MPEC best responses.
   Run this only after an OK, since it is an equilibrium loop.
3. Check I4's N5 mechanism (dispatch and prices at K = 50, 75, 147).
